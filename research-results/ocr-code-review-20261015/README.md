# PDFなしの英数字認識・確認操作の改善（2026-10-15）

利用者の指示に従い、PDFの提供を待たず、独立した架空の文字画像だけで比較した。
単独の英数字・数字コードでは英数字用モデルを呼んでいなかった条件を修正した。
重み・辞書・ダウンロード容量・日本語モデルは変更せず、追加学習はしていない。
これは文字認識の部品評価で、本番資料やPDF全体の精度の実証ではない。

## 新しい文字列での変更前後

`fresh-content-validation-v2/paired-routes.json`は、同じ入力と同じprobeで、
変更前e9518eeのInfrastructureと修正版の実際の`OcrAsciiRefinement`を別workerで実行した比較。
日本語の生出力を製品の変更前結果として代用していない。
生成条件・正解・入力・readerを先に固定し、両workerの正常終了とSHAを確認した。
最初の比較で消費した文字列は除外した。字体は既に観測済みなので未見字体の評価とは呼ばない。

4字体×2サイズ、通常コード192件と紛らわしいコード192件。
紛らわしいコードはI/l/1/O/0を多く含む意図的な難例で、実際の出現割合を再現していない。
通常コードには数字のみ、Lab-/Rm-、英大文字＋数字等を含む。

| 原印字bbox＋2px・384画像 | 変更前 | 修正後 |
|---|---:|---:|
| 通常コード192件の完全一致 | 192 | 191 |
| 紛らわしいコード192件の完全一致 | 68 | 81 |
| 合計の完全一致 | 260 | 272 |
| 誤読数 | 124 | 112 |

14件改善・2件悪化、誤読数は約9.7%減った。この難例を半数含む集合の一致率を、
以前の時間割本文の一致率や実資料の精度と直接比較しない。
悪化した2件は、Sawarabi Minchoの`Oll82`→`O1182`とKleeOneの`914`→`q14`。
失敗を残したまま、同じ未使用評価を見て個別文字の置換規則を足していない。
confidenceが高い誤読も残る。原画像との確認を省略する根拠にはしない。
native最小confidenceが0.8以上の誤読数は66→66で、この診断指標は改善していない。
文字単位の編集数は184→167。比較workerの最大working setは約435MBだった。
CPUは各session 2スレッドで実行し、比較には複数モデルの読込と別workerの並行実行を含むため、
この試験全体の時間をアプリの文書処理時間とは扱わない。

6px余白の別条件は259→267完全一致、8件改善・悪化0。
同じ384画像の対条件なので、2px条件と合算して独立な768資料とは数えない。
6pxへの変更は行っていない。4つの白画像は新旧とも空出力だったが、
これだけで損傷・切断・空欄検出の資格は与えない。

## モデル・余白の探索比較

`exploration-v1`はSawarabi Gothic／Minchoと新しく取得したKleeOne／KaiseiTokuminの4字体。
384コードの2余白条件と4白画像、3モデルで2316回の認識を実行した。
各余白条件の新字体の通常コード96件は、日本語V6／公式英語V5が96件一致。
学習済み英語V5は2pxで94件一致だった。
新字体の紛らわしいコード96件は、2pxで日本語V6が29件、公式英語V5が18件、
学習済み英語V5が56件一致。単純な公式モデルへの交換は選ばなかった。
6pxは学習済みモデルで49件一致に下がり、余白を広げる案も選ばなかった。
この探索集合をルーティング選択に使用したため、修正後の独立評価には数えない。

単体字形の墨・送り幅も保存した。Sawarabi GothicではIとlの単体墨が同じ場合がある。
送り幅や前後文字の位置は異なり得るので、文字列全体が必ず識別不能とは断定しない。

## 製品の変更

- 日本語接頭辞がない、2～32文字の数字を含むASCIIコードにも既存の英数字モデルを使う。
  1文字の時限、英語の文章、句読点を含む行は新しい対象にしない。
  native .8／reject .05／padding／元の文字数の条件を保ち、失敗時は日本語の原観測を残す。
- 高信頼度でも、未確認の英数字混在コードに含まれるI・l・1・O・0の文字種を確認画面で明示する。
  原文・native confidence・Validator・採用権限は変えない。確認後は同じ注意を繰り返さない。
  この表示は文字種の注意で、誤読の全件検出器ではない。
- 表示中のクラスの教室欄を、曜日をまたいで一括選択できる。選択解除も追加した。
  既に確認済みの対象も合計128件の上限に含め、上限を超える一括選択は一部だけ追加しない。
  訂正入力はConsolasを指定し、似た英数字を区別しやすくした。

LinuxでIntegration991件、Core288件、変更に対応する38件のfocused検証、
Windows対象のUI helperビルドが成功した。Windows上の製品ビルドと実操作は
[CI38691119306](https://github.com/n624-dev/takupoke-win/actions/runs/38691119306)で確認する。
利用者の発見・訂正時間は未測定。UI自動操作の時間をその代わりにしない。

この変更は開発ブランチ・PR向け。既存の配布版0.1.0-dev.10439には含まれていない。
iOSは編集せず、内部Markdownは公開しない。
