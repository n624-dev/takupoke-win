# 日本語付き教室名の候補表示

名称対応表の教室名に日本語や途中の空白があっても、I/l/1・O/0だけが違う登録値を候補表示する。
日本語と空白は完全一致が必要で、接頭辞を外す処理・空白削除・類似した日本語名の生成をしない。
ASCII数字を含む2〜64文字、最大2置換、登録4096件・候補3件まで。
別クラス専用値を除き、結合欄では対象となるすべてのクラスに適用できる登録のみ使う。

候補を押すとその入力欄だけに値を入れ、同じ候補の再選択でも確認チェックを解除する。
原OCR・confidence・出典を保持し、人の画像確認・全体プレビュー・明示採用が必要。
確認の代わりに候補を自動採用しない。

閉じた[接頭辞画像のOCR結果](../ocr-manual-tail-20261016/README.md)を再認識せず、
旧候補関数と新関数で比較した。参照表はOCR終了後、候補worker開始前に、文字列SHAの半数と
独立した未使用64値から固定した。これは**事後の入力補助の候補網羅率**で、新しいOCR精度試験ではない。

2px・384画像のOCR292一致は両方同じ。誤読92件のうち正解が表にある44件に対し、
旧関数は日本語を対象外として正候補0件、新関数は34件に正候補を出した。
既に正しい16件、正解が表にない15件にも別候補が出た。候補ありは60画像。
6pxはOCR257一致、正解が表にある誤読61件中54件に正候補、既に正しい14件・未知15件にも候補が出た。
6pxへ切り替えず、34件や54件を訂正済みの正解数へ加算しない。
利用者の選択ミス、訂正時間、実資料での候補網羅率は未測定。

Core301件とWindows UIのクロスビルドが通過。日本語の文字違い、空白の違い、改行・先頭空白、
接頭辞のない登録値を誤って候補にしないことを検証した。
配布時の実Windows UIは日本語付き候補の選択、再確認、全体プレビュー、元OCR保持を検証する。
[元ASCIIコードの独立試験](../ocr-room-candidates-20261016/README.md)も別記録として保持する。
