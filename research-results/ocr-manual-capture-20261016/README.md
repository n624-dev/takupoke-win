# 復旧時の英数字を、原画確認へつなぐ（最初の単独コード比較）

この記録は最初の単独コード変更の評価。後に日本語を保った英数字末尾へ範囲を広げ、
[別の新画像とWindows帳票全体](../ocr-manual-tail-20261016/README.md)を検証した。
以下の原出力・集計は変更していない。通常Readの条件とモデルは引き続き維持する。

復旧用の`ReadForManualCapture`では、日本語OCRの低信頼度文字は原画像の確認対象として保持する一方、
英数字OCRの低信頼度文字は捨てていた。日本語OCRが高信頼度で誤読し、英数字OCRが低信頼度で正しく読む場合も、
誤った日本語側の文字が残っていた。

復旧用の単独コードに限り、英数字OCRの元のconfidenceを保持して使う。
0.8未満の文字を含む項目は従来どおり原画像の個別確認が必須で、confidenceを引き上げない。
通常の`Read`の0.8条件、reject 0.05、入力padding、元の文字数、取得範囲、全体プレビューと明示採用は維持する。
日本語接頭辞のある末尾、既知のクラス名、表より上の見出しには、新しい低スコア条件を適用しない。
モデル・辞書・ダウンロード容量はこの変更では変えていない。

## 同じ原画像での変更前後

seed202610161217、新しい文字列、既観測4字体×2サイズ。
通常コード192画像、I/l/1/O/0の難例192画像という人工的な半々の構成。
過去のコード比較2回、名称候補比較、同時進行の学習train/devの文字列を生成前に除外した。
正解・入力・モデル・readerを固定してから実行し、正常終了とSHA照合後に比較した。

変更前の実バイナリでも同じ入力を実行した。通常`Read`相当のrouteは、
2px/6px/白画像の全772件で文字列・confidence・CTC由来glyph・呼出数が完全一致した。
日本語モデル単体を変更前の製品結果として代用していない。

| 原印字bbox＋2px・384画像 | 変更前 | 復旧用の新経路 |
|---|---:|---:|
| 完全一致 | 259 | 292 |
| 通常コード192件の一致 | 191 | 190 |
| 難例192件の一致 | 68 | 102 |
| 文字編集数／1,871文字 | 180（9.62%） | 106（5.67%） |
| native 0.8以上の誤読 | 82 | 24 |
| native 0.8未満を含む画像 | 55 | 143 |

40件改善・7件悪化、本文に相当する画像の必須確認は88件増えた。
誤読を減らす一方で、確認せずに使える数を増やす変更ではない。
高信頼度の誤読24件も残り、原画像との全体照合を省略する根拠にはならない。
人が訂正を完了した後の正解率・発見時間・訂正時間は測っていない。
384画像は1文書ではないため、文書ごとの128項目上限とは比較しない。

6pxは同じ384画像の対条件で255→276一致、33改善・12悪化、低スコア画像60→157。
6pxへの変更はしない。白画像4件は両方空のままだが、損傷・切断拒否の資格にはしない。
比較workerの最大working setは439,996,416 bytes（約420MiB）。
複数モデルと両routeの比較、追加学習の並行実行を含むため、処理時間をWindows文書時間へ換算しない。
製品で増えるモデル呼出しはなく、既に得た観測の選択だけを変える。

## 検証範囲

Core300、Linux Integration1113、英数字のfocused11件を通過。
既定routeの保持、低スコアを昇格させないこと、元crop内のCTC位置、日本語接頭辞、
クラス名、表より上の見出しを検証した。原画確認・128項目上限・古い入力拒否・明示採用は既存の検証を継続する。
クラス名と上部見出しの保護は孤立画像の実行開始後に追加したため、この表の精度改善には加点しない。
実行時sourceと追加後sourceを分けて残し、Windowsの帳票全体を別途再検証する。

新しい字体・未知の帳票・実資料の精度評価ではない。
同時進行の追加学習とは分離し、この表では旧配布モデルを両経路で使用した。
学校の実資料・その派生画像は使用せず、iOSは編集していない。
