# 製品OCR接続とWindows取得経路の確認（2026-10-15）

既定のCPU構成を日本語PP-OCRv6 medium＋追加学習英語PP-OCRv5へ接続し、実際の製品factoryで測定する。
原画像のconnected ink所有を先に確認し、原印字bbox＋2px、全CTC、native confidenceを維持する。
英数字の原画像分割と選択条件は過去の固定比較と同じ。学校資料は一切使わない。

開発用の同じ2字体・3クラス・5ページ・120枠・本文360項目では、製品処理で330/360／319/360、
CER1.3357%／1.81496%を再現した。両文書とも欠落0、元画像crop付きの確認を準備できる。
参照から数えた実際の訂正＋必須確認の合計は38／41項目。新しい128項目上限に収まる。
これは利用者の実作業時間や照合済みという主張ではない。
5ページの処理約54–56秒、プロセス最大RSS約579MB。CPU推論thread2、参照正解は両workerが終わるまで読まない。

Windows条件は学習に使っていないSawarabi Gothic／Mincho、別の固定生成seed、正例2・曜日欠落2・クラス欠落2。
最初の条件と判定値は生成前に固定した。ただし取得倍率・解析の修正には同じ資料の失敗を参照しており、
再実行は修正後の全文書回帰検証である。完全な未見の盲検評価や実資料への一般化の証明とは扱わない。
実機はWindows runnerの物理2／論理4CPU、メモリ17,174,360,064B。実学校資料の成功率と換算しない。
導入の確認は誤読0でなく、取得の完全性・CER・訂正負担・負例・CPU負荷で判断する。
生成前の条件（各正例全120枠・全360項目、各字体CER3%以下、訂正＋確認128項目以下、負例4件拒否、RSS6GiB以下）を保持する。

失敗も別条件として残す。全てbyte/SHAを複製時に検証し、元のraw／gateを書き換えない。

- development-v1：製品factoryによる原画素の開発再現。推論終了後の検査と凍結sourceを保存。
- native-default-scale-failed-v1：元のWindows描画倍率で、全6文書が範囲所有の確認で停止。
  primary／英語の文字推論0、detectorのみ12回。精度・負例の資格加点なし。
- native-png-scale-failed-v2：PNGを明示しても同じ停止。診断用の架空1ページはローカルにだけ保持。
- native-144dpi-bare-label-failed-v3：PDFサイズのDIP単位を正しく144DPIへ換算した後、範囲確認を通過。
  Gothicは120枠・360項目、CER1.3735%。MinchoはOCRでラベルのコロンが抜け、Builderで停止。
  原読取を使った別のゼロ推論検査では、ラベル認識の修正後に両文書120枠・360項目となった。
  その検査にはempty判定・crop取得・利用者確認の権限がなく、最終資格には数えない。

コロンの欠落は文字の生成やconfidence修正で補わない。元の完全なnative行の先頭にある
既知の科目／担当／教室ラベルを、元のglyph境界と独立する行範囲で扱う。
本文内の役割語はそのまま残す。旧17クラス・680枠のordered-row条件は変更していない。
Windowsでの完全な再実行は下記v4に保存した。旧条件の失敗は変更しない。

生の文書には、架空資料の照合crop画素が含まれる場合がある。全ページ画素・PDF・学習重み・nativeバイナリは
研究記録に含めない。配布する学習モデルは別のmodel-artifactsにSHAとApache2ライセンスを付けた。
内部方針MDは公開しない。iOSリポジトリは編集していない。

Windows製品UIの検証：b57ad91の[CI38661859613](https://github.com/n624-dev/takupoke-win/actions/runs/38661859613)は全7ジョブと789 UI checksを通過。
原画素の一致、高信頼度の単項目訂正、複数選択、以前の入力保持、中止復帰、新しいsession、
変更なしの見出し確認、明示採用、再起動後の正式結果を確認した。これはOCRの精度とは別の操作検証。

事後に保存済みrawと参照を項目別に照合すると、各字体の科目・担当はそれぞれ120/120一致し、
誤読31／23項目は全て教室欄だった（教室89/120／97/120一致）。年度2029・前期・3クラスの見出しも一致した。
これは同じ架空資料の内訳であり、新しい独立評価や実資料での科目・担当の無誤読保証ではない。

両正例は登録したCER3%／全枠・全本文／128項目／RSS6GiB条件を通過し、曜日欠落・クラス欠落の計4負例は全て拒否した。
CPU推論thread2、最大プロセスworking set459,378,688bytes（約459MB／438MiB、同reader全6文書）。
時間はダウンロード・初期smoke・利用者の照合時間を含まない。画像は実際のWindows APIでPNG・144DPIへ描画した。
30ページの画素は生成前の原画と一致しておらず、Windows描画後の画素に対して元印字の所有確認を通している。
文字値・confidence・出典を参照正解で修復せず、そのまま評価した。

同じ資料・解析で比較したV5 mobileは、Gothicで本文192項目欠落・取得168項目中149一致、Minchoで読取停止だった。
旧V5のCER2.277%は取得できた1054文字だけの条件付き値で、全2257文字を読む改善構成との単純な差分比較にはしない。
高信頼度誤読は残るため、confidenceだけで原画像照合を省略できない。31／23項目は参照正解による事後診断であり、
利用者が誤読を見つける時間、全資料の照合負担、実資料の成功率を測ったものではない。

この条件の成功は、原画像を確認・訂正して明示採用するWindowsの導入構成の検証である。
スキャン・未知の書式・実学校資料・ARM64実機の品質保証とは扱わない。現在のUI操作手順は
[AI・OCRの設定](../../documentation/ai-settings.md)を参照。
