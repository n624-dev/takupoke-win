# Actual Windows PDF render of the consumed invented control

One already-consumed, wholly invented unlabeled 40-slot pixel source is wrapped losslessly in an image-only PDF. This is development endpoint evidence, not a fresh holdout, OCR qualification or recovery success. The generator and this Windows test never read a private school PDF. All text/coordinates are the independently invented source already used in the prior PNG experiment.

The shared image-only wrapper is byte-identical to iOS source commit `4b08662d3c4613b22ffad5c0263915a14771e324`. Original PNG SHA256 is `3bb95ebcce616cf24c6b4c431f6fe9b790491e5d22085f74e4430cfd5871b946`; PDF is 41,545 bytes with SHA256 `7ceb34d191dc48a5d6bc072e75898172cd20f356f6c9c312f558635d6a454323`. The PDF has one 3740×800 page, matching MediaBox/CropBox, rotation zero, one RGB FlateDecode image, no text/font objects and `Interpolate false`. Independently decoded embedded RGB equals the original pixels (`62f80f469cd0d36cb98ddc8ecebee71c94a278c2ee3c7e22336688f844e38fd9`). The PyMuPDF 1× RGBA check is separate from the forthcoming actual Windows render.

The Linux generation job uses fixed Pillow12.3.0/PyMuPDF1.26.6 and the original public Noto CJK font. Its exact known font/code/source/pixel/PDF hashes must match before Windows runs. It transfers the wholly fictional PDF through bounded transient job outputs; neither PDF/font/image binaries nor outputs are committed, uploaded as Actions artifacts, or stored in caches. Source remains source only.

Windows calls actual `PdfPigLayoutReader.Read` once, retaining its raster-only capture and expected `raster` refusal. It then renders that same actual PDF once using the product's Windows.Data.Pdf dimensions: round(pageWidth×2), clamp640..2400, proportional height, then height cap3200. For this page the requested result is 2400×513. BGRA8/Ignore alpha/no color management match production. Original PDF identity, native page size, encoded rendered image hash and decoded actual BGRA hash are recorded separately. No local interpolation or alternative render is substituted.

This workflow invokes no OCR, model, Builder, provider or adoption. Models remain inactive. The actual rendered pixels may later feed a separately frozen research OCR recipe; original whole text atoms/cell geometry, actual ink/ownership guard and full literal formal comparison remain necessary. Bitmap provenance alone proves neither transcription confidence nor correctness.

Large observations use numbered bounded console chunks with byte count/SHA256. Restoration requires exactly the one expected report ID, rejects duplicate/missing/changed chunks, and must verify decompressed BGRA shape/hash and original encoded image hash. A short summary is always emitted. A successful workflow with missing observations is not a complete measurement.

Cleanup removes only marker-owned temporary generated inputs/font/render outputs, including failure paths. The Linux regeneration, transport counterexamples and actual Reader preflight are source/observability tests. SDK compilation is not a native renderer result. Product sources, schema, validator, public releases and other workflows remain unchanged.
