# Japanese-font ASCII adaptation v3

This separate, inactive research trial adapts PP-OCRv5 English to ASCII glyphs inside Japanese fonts. The actual initializer and teacher are **font-balanced-v1 epoch 4** (`7313bee5…`), corresponding to the current English ONNX (`9dd3ed77…`). The foundation is the pinned official Hugging Face PP-OCRv5 English architecture and full 438-class dictionary. This is not initialization from untouched official weights; the rejected Latin-font v2 is not used.

`protocol.json` fixes fonts, new synthetic strings, controls, optimization and development selection before inference. Training code glyphs use previously consumed Sawarabi Gothic/Mincho, Klee One and Kaisei Tokumin. Zen Old Mincho/Yusei Magic are separate development code families; Shippori Antique/Zen Antique Soft are separate fresh code families. Four reused Latin families provide natural English and printable retention checks. Exact white tensors are repeated physical controls, not independent held-out examples. Prior public synthetic labels, PNG/input hashes and normalized root BGRA crops are exclusions only.

The model reads separated ASCII suffixes. It is not trained to generate Japanese room prefixes. Arbitrary letters, digits, separators, short codes, random-position confusables and paired single-glyph variants avoid a fixed room-code grammar. The complete crop ink, baseline, relative glyph height and gaps are preserved. Full FP32 softmax, original preprocessing, CTC runs/confidence, valid-width padding refusal and the uncalibrated reject output stay explicit. No dictionary/output repair is used.

Run `download_fonts.py`, then `train.py` once in the established training environment. `fresh.py` opens the registered fresh set once after immutable development selection; no optimization or reselection follows. A useful candidate can be exported with `portable.py` and packaged with `package_portable.py`. The research report records failures and qualifications. Raw crop improvements do not activate a model: the parent evaluates the actual C# routes, fictional full documents, provenance and confirmation burden.

Scratch is `/workspace/scratch/ascii-english-v5-japanese-fonts-v3`; data/checkpoints/caches stay outside source control. The independent Japanese primary and iOS repository are untouched. No CoreML/iPhone qualification is implied. Public fonts are OFL; the foundation is Apache-2.0. Exact hashes and licenses accompany the portable candidate if exported.

The original trial is now closed and FAILED; it selected active v1 and left fresh unopened. See the [research report](../../../research-results/ocr-synthetic-training-20261013/ascii-english-v5-japanese-fonts-v3/README.md). `exploratory_epoch1.py` is a separately authorized failed-gate exploration for consumed native routes, with independent fidelity receipts; it does not run the original successful-candidate `portable.py`/`package_portable.py` path. Postfit, source geometry and distortion scripts are descriptive failure diagnostics, never new model selection. The separately prepared v4 protocol is draft-only and its optimizer is held by the parent.
