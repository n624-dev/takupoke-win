# Windows標準OCRの研究比較

公開架空の既消費192原行だけを、Windowsのインストール済みja-JP/en-USエンジンで読む。
独立原文は子プロセス終了後の採点にのみ使用する。PNG・復号したBGRA・元寸法を検証する。
初回の元寸法条件では全印字行で検出0だったため、別recipeで各原画素を3x3反復し、
固定32px白余白を加える。原画素の切断・補間・原文による選択は行わない。
生の全文字列・単行文字列・拡大入力での単語箱・角度と入力SHAを保持する。

Windows APIは項目の認識信頼度を公開しないため、スコアはnullのままにする。
0.8等の値を付与して現行Validatorへ接続しない。成績は完全一致の診断に限定し、
PDF取得・元インク所属・本文最大3訂正・アプリ採用の資格とは扱わない。
対応言語がない場合やnative APIが使えない場合は、0測定／未評価として失敗を保存する。

専用Windows Actionsはインストール済み言語機能を記録する。公式日本語OCR機能の導入は
8分上限の別dispatch optionとして保持する。初回の導入試行は失敗し認識前に停止したため、
同じ取得をpushごとに繰り返さず、まず導入済みの英語エンジンを拡大入力で比較する。
日本語未導入の結果を日本語の合否へ数えない。資料を機能取得へ送らず、推論と採点を分離する。
モデル配布や製品設定の変更はない。架空rawはハッシュと元の改行を維持した行単位JSONで
ログへ保存し、作業用出力・NuGetを削除する。実資料・利用者の画像は渡さない。
