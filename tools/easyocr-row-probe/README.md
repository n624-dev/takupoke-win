# Uniform EasyOCR Japanese recognition probe

One CPU recognizer-only arm uses the identical 170 original pixel rows from the already consumed invented unlabeled40-slot development image. The original PNG/RGB/ROI list is regenerated and checked before any forward call. No school PDF/image, gold coordinates, expected words or role labels enter the worker. No pixels/PDF/font/model weights are tracked.

Official EasyOCR source363afb184047ce452e436f4224f3098422df872e and japanese_g2 weights are pinned. The Reader actually uses detector=False, download_enabled=False, CPU and quantize=False. Public get_text uses all2214 published model characters (ignore_char empty), greedy CTC, one forward per row, no contrast retry (contrast_ths0), no rotation/whitelist/wordbeam/paragraph repair. Quantization and automatic contrast retry are explicit differences from Reader defaults, fixed before output. Optional wordbeam lexical dictionaries are not acquired; the unchanged official converter permits their absence and greedy decoding never consults dict_list. Required ja/en character assets are preserved byte-exact.

The unchanged official input route is RGB-to-grey, get_image_list/calculate_ratio/compute_ratio_and_resize then AlignCollate/PIL BICUBIC64-height/NormalizePAD. Narrow inputs retain the actual official vertical/aspect handling and replicate-last-column right padding; no custom orientation/width correction. Actual preprocessor image dimensions, normalized input tensor shape/SHA and forward count are reported. These settings form one new recipe; no old outputs are replaced or selected per cell.

Recognition returns text and an uncalibrated custom_mean sequence score. Source boxes are the original pixel-support ROI, not predicted word/character geometry. Production wire confidence remains None. Raw output availability/geometry does not establish acquisition eligibility, role ownership, full formal correctness, blank proof or model qualification. The actual Strict/Builder/Validator/formal host replay and independent gold comparison occur only after inference, including incorrect formal proposals.

Pinned CPU torch2.5.1+cpu/torchvision0.20.1+cpu plus exact wheels run in an isolated Ubuntu24.04 CI venv; no detector or other model download, cache or artifact upload. All data is fictional. One170-row call set is bounded to600seconds, sampled own-worker RSS2GiB, sampled raw32MiB. Native API return, serialization, errors and empty output are separate. Exact partial raw/stderr bytes and hashes are transported even on failure; cleanup deletes only this run's marked temp directory. Linux CPU/hosted runner inference is not Windows/physical-device evidence.

The input is consumed development, not unused holdout or actual Windows PDF render2400x513. Body/header/complete tuple/formal and runtime-error denominators stay separate. No posthoc digit correction, inferred1..8, word repair, clipping, best-of-output selection or model activation. A missing/incorrect output remains a failure. Original source scripts/fonts and Apache2.0/CC-BY inputs retain their notices; no weights/binaries are distributed. No native result exists before this source freeze.
