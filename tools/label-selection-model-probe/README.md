This is an isolated development experiment after both CPU candidates scored 0/6 exact positive documents with Japanese-readable JSON. It never activates a model catalog or modifies the application Provider, decoder, certificate, Rules or Validator.

The model selects only original label group IDs. Each of the required `subject`, `teacher` and `room` arrays permits the **same complete supplied source-ID enum**, with 0–48 entries. No role-specific ID filter, expected answer, field value or oracle enters the grammar or prompt. Supported role-label names are the application's public vocabulary. The prompt has no fake example IDs.

The recipe is `label-selection-json-schema-no-tools-v2`: Foundry.Local.WinML 1.2.4, CPU, temperature 0, random seed 17, maximum 512 output tokens, `json_schema`, `tool_choice: none`, readable Japanese JSON. These settings are explicit requests; actual runtime schema support must be demonstrated by the native run. The SDK's settings container is read-only, so its individual properties are set before generation.

The v1 native run at source `cd56ab3` returned 12 completions per model with no runtime errors, but both candidates scored 0/6 exact positives and rejected all 6 negatives. Outputs included fenced arrays, text labels, scalar values and body IDs; the requested schema did not constrain the observed output. An independent check of the pinned SDK's actual request serializer confirmed that the complete schema and sampler settings reached the native request, while `tool_choice` was absent. This v2 control changes only that generation setting to `none`, following the [official Foundry recommendation for JSON without tools](https://github.com/microsoft/Foundry-Local/blob/main/docs/Structured%20Outputs.md). The prompt, schema, decoder, measured-cut reconstruction and corpus stay identical to v1. A successful CI job alone does not prove that the native backend enforced the schema.

The adapter strictly decodes raw label arrays and preserves model order. It reconstructs only measured cut IDs, then calls the unchanged production physical certificate, rebuilds the document and runs the real Engine/Validator with a complete result oracle. Production Rules safety preflight rejects ambiguous ownership before the model is called. A malformed output or failed certificate is terminal; no retry, fallback, correction or expected-answer substitution occurs. Rules-resolvable examples are explicit model correctness controls and do not demonstrate useful AI recovery.

The development corpus is the previously inspected 6 positive and 6 negative documents across ordinary, exam and return kinds. Their document fingerprints are emitted before inference. The independent oracle is used only for scoring/preflight. Each scored completion retains a bounded 16,384-character prefix with its original length and truncation marker; selected IDs, adapter stage, Provider attempts, native completion attempts/returns and positive role obligations are recorded. Over-limit completions fail safely. A strict decoding failure fails all three positive label obligations; runtime exceptions remain separate, with assessed and eligible denominators shown. No extra diagnostic generation is substituted into scoring.

`--preflight` performs no model download or native initialization. It checks 6 oracle-selected adapter certificates, 48 malformed-output rejections, 6 role-swap certificate rejections, and the three production Rules/Builder/Engine/Validator/formal-converter controls. The native model command first checks the four required Microsoft Visual C++ x64 CRT DLLs in System32; missing prerequisites are reported with the official installer URL before any model download.

The native workflow downloads only pinned public models into a dedicated temporary cache and cleans that cache normally. It prints console logs and uses no Actions artifacts or caches. Its exit code is nonzero for operational errors; a completed job can still have `developmentCorpusStatus: failed`. This stage does not establish heldout correctness, PDF Reader/OCR behavior, physical-device performance, minimum memory, NPU support or catalog qualification. Process memory measurements exclude child processes. The downloadable physical QA benchmark at source4446168 remains a separate, earlier recipe.

Before any final heldout run, freeze the provider/protocol/sampler/recipe and corpus manifest; the independent referee supplies distinct case families. Tuning from a heldout answer converts that case into development evidence.
