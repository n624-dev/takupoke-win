# Complete source-colour acquisition comparison

This compatibility study reuses the consumed ordered-row source content and
geometry. Each frozen PDF contains five pages, all17 classes×5 weekdays×8
periods,680 slots and2040 body values. Only opaque fill/stroke RGB colours change
for the positive counterparts: black, red, blue, neutral gray and mixed colours.
It is not a new independent model or OCR quality denominator.

The actual source-only `ordered-row-e2e` child receives only the PDF and its
hash. Reader, Strict, captured-layout Builder, Rules, Engine, Validator and
formal converter run before the external scorer sees expected literals/roles.
No OCR/GenAI, manual correction, raster oracle, class repair or saved adoption
is performed. Same bytes/oracle compare the pinned pre-change baseline and the
candidate. Baseline readable refusals remain failed recovery, not safe negatives.

Near-white, white, nonopaque text, later whole-page covering paint, missing class
and missing body controls must refuse in this bounded source route. A refusal
proves this route's supported scope; it does not say a lighter/transparent PDF
can never be read by a separately verified image route. Execution errors and
incorrect formal acceptances fail the comparison. Original capture/version/cache
and negative contracts are also exercised in the integration suite.

The generator uses the original pinned public Noto font installer. PDF/font
files belong only to its new owned temporary directory and are not committed.
Reports retain source/manifest hashes, outcome, source completeness, glyph/cell
counts, role-proof counts, time, complete literal equality and zero model calls.
Colour bounds do not reinterpret semantic colour meaning such as cancellation.
