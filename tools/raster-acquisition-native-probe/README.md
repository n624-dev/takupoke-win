This isolated benchmark executes the actual PDF Reader/Strict parser, linked production Windows PDF renderer/OCR/Builder, Rules, Engine, Validator and formal converter on nine entirely invented image-only PDF documents. It uses no LLM Provider, school input, school endpoint, saved adoption, app catalog or production source change.

The 45 frozen RGB PNG pages and separate literal JSON oracles were drawn from known text using NotoSansCJK. PNG, literal-oracle, PDF and font hashes preserve provenance. The standard-library `fixtures/assemble.py` embeds the exact PNG compressed pixel stream in a lossless PDF, with no hidden text/OCR layer. It checks every source-image and reconstructed-PDF SHA. Ordinary, exam and return documents contain all 40, 510 and 680 required slots respectively, across five pages; special documents cover all 17 classes. The independent oracle checks the complete slot set, classes/days/year/term, every formal lesson/value and every special date/period clock. It never derives expected characters from OCR or the production engine.

Controls include clean documents of all three kinds, two distinct I/1 and O/0 strings, genuinely blank teacher/room values, unreadable covered ink, small fonts and a 90-degree image rotation. Confidence and OCR-source evidence do not prove transcription correctness: any Validator-accepted result differing from the literal oracle is counted as `incorrectValidatorAcceptances`. Unreadable input must fail safely. Preview/Validator acceptance remains separate from a saved adoption.

Exception-based negative credit is conservative: only the unchanged OCR's two exact unreadable-character/uncovered-ink rejection sites count as confirmed input rejection. Other acquisition exceptions, including missing OCR artifacts/dictionary or insufficient memory, remain `unassessedAcquisitionFailures`, give no negative credit and make the job fail. Completed document/Engine rejection remains separately visible. Formal scoring includes both recorded/displayed lesson time and every date/period clock.

`readablePositiveRejections` counts an assessed readable positive that the pipeline refuses as recovery failure, never as correct negative rejection. Success, expected negative rejection, incorrect acceptance, assessed denominators and unassessed acquisition/execution failures remain separate. Installer/prerequisite failures emit a partial report and leave all remaining documents unassessed.

The OCR installer is the actual production pinned approximately21MB Paddle bundle/store and smoke test. The unchanged production acquisition routine may select ready Windows OS OCR or fall back to that bundle; this baseline does not instrument or infer the selected backend and makes no NPU claim. It preserves the actual raster ink checks, confidence bounds, work limits and cancellation. No crop/upscale/orientation preset or semantic inference is added at this stage. Strict raster failure is eligible for an independent render attempt through the existing RecoveryPolicy; incomplete text capture is not treated as completed text.

The Windows2025 workflow runs only for this tool's research-branch changes or an explicit manual dispatch. It assembles the frozen PDFs, builds the native unpackaged console and emits fictional console results. There are no Actions artifacts or caches. The model cache is uniquely owned and normally removed. A completed report containing safe rejections is acquisition evidence, not a quality pass; initialization/native errors must be assessed separately. Process peak memory is cumulative and excludes child processes. The Linux compile check disables self-contained Windows manifest tooling, which cannot execute on Linux; only the Windows job establishes native build/execution.

`--preflight` checks only the fixed fixture identities and literal/PDF hashes, with no OCR initialization or model download. It does not establish native prerequisites, OCR correctness or pipeline success. This benchmark is separate from model component A/B results and cannot activate a model catalog.

`--tensor-diagnostics` is a separate forensic mode, with no quality denominator or recovered document. It renders the first page of each unchanged PDF using the production dimensions and native Windows renderer, opens the actual pinned production Paddle sessions, and reuses the private production tensor preprocessing by read-only reflection. It records rendered pixels/PNG hashes, raw input/output tensor shapes, float-byte hashes, extrema, nonfinite and out-of-range counts with the first eight offending values/indices/bits, the original detector boxes, CTC text and individual character confidences. Full-page and bounded crop-envelope PNGs are retained in the fictional console report; envelopes are for inspection and do not replace the fractional source sampling. At most 64 original crops per page are inspected. These crops can include later regions past the baseline's first rejection; this mode cannot identify an unobserved failing baseline page or infer which OS/fallback backend the baseline used.

The existing `Timetable-confusable-2` input additionally runs exactly one optimizer-disabled detector contrast on the same input tensor. Every other call uses the production optimizer-enabled sessions, BGR normalization, nearest sampling and unchanged 0.8/range checks. No clipping, softmax insertion, character repair or oracle-fed OCR is performed. Managed/native ONNX runtime identity and runner-visible CPU/RAM/OS are logged. Each page has a 90-second cooperative cancellation deadline and the same 20-minute lifetime; synchronous native inference is checked after it returns and is not forcibly interrupted. An error is an unassessed diagnostic execution failure, never a correct negative or model-quality verdict.

Research-branch pushes now run tensor diagnostics to investigate the observed baseline failures. Manual dispatch selects `tensor-diagnostics` (default) or `baseline`, which runs the unchanged full acquisition scoring recipe. Neither mode changes the frozen fixtures, literal oracle or production acquisition code.
