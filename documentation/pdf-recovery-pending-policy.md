# PDF復旧・OCR・ローカルAIの未実装方針

この文書には未実装の方針だけを置く。実装できた項目は削除し、完了記録・進捗・実測値・失敗理由・作業メモは残さない。

対象はiOS・Windowsの通常時間割、試験時間割、試験返却時間割PDF。時間割変更XLSXとAPIで取得する学校行事は対象に含めない。

## OCRとローカルAIの並行比較

- 同じ架空資料で「現在の処理」「OCR＋テキストAI」「OCR＋テキストAI＋局所画像の再確認」を比較する。生成条件・入力・Validatorを固定し、構造解釈と文字認識を別に評価する。
- テキストAIには元の行、座標、セル候補、周囲の見出しを渡す。科目・教員・教室の分類、授業同士の対応、結合・並記、注記と本文の区別を小さい単位で判断させる。
- 出力は原文ID・認識候補IDの選択を優先する。値は選択した根拠から再構築する。自由な全文書き換えや欠落授業の創作を認めない。
- 認識候補を複数保持し、「どれでもない」「不明」を選べるようにする。文脈や語彙だけで文字を確定しない。
- 画像対応AIには曖昧なセルと必要な周辺部分だけを渡す。初回はOCRの答えを伏せて再読させ、その後に照合する条件も比較する。
- AIの訂正候補は元の文字列・原画像・正しいセルへの所属と照合する。根拠が確認できない候補は未解決のまま残し、信頼度やAI同士の一致だけで採用しない。
- AIが要求できる追加操作は、範囲を限定した切り出し、原本からの再描画、別OCRによる再読に限る。回数・面積・時間・メモリの上限を固定する。PDF内の文言を命令として扱わず、AIに通信や採用確定の権限を渡さない。
- 文字入力・画像入力・構造化出力の対応をProviderごとに判定する。実行先を明示的に端末内へ固定し、Private Cloud Computeを含む端末外へのフォールバックを設けない。

## 直接抽出・画像取得・領域認識

- PDFの文字、位置、罫線、セル境界を取得できる範囲を広げる。色・フォント・描画方式の違いを検証し、OCRは不足部分に限定する。
- 直接抽出とOCRを同じ座標系で照合する。ページ回転、CropBox、領域の原点、縮尺、境界の扱いを検証し、不一致を都合のよい結果で上書きしない。
- 全体で表の構造を確認し、重なりを持つ領域で小さい文字を検出する。境界の欠け、二重登録、隣セルの混入を検証し、読み順を単なる処理順から決めない。
- ベクターPDFは必要領域を原本から高解像度で描き直す。画像PDFは元画像の情報を失わない経路を使い、拡大だけで細部が復元したと扱わない。
- 描画後から認識直前までの縮小・切り出しを検証する。画像取得、検出、切り出し済み画像の認識、文書全体の組み立てを別々に評価する。

## 構造と重要項目の照合

- 元のOCR行、文字順、切り出し領域、罫線で確認したセルの所属を保持する。推定した文字間隔だけで日付や見出しを分断しない。
- iOSのDocumentObservationから表・セル・結合範囲を取り出し、元の行・文字との対応を検証する。文字が認識されていない場合と、認識済み情報の取り出しを失敗した場合を区別する。
- 日付、クラス、時限、教室番号、並記の区切りは高信頼度でも別経路で照合する。並記は本文だけでなく複数行・左右配置・教員との対応も確認する。
- 罫線による解析と表構造専用モデルを比較する。モデルの行・列・セル・結合範囲を文字位置や物理境界と照合する。
- 文書向け画像言語モデルは難しい表・セルの比較候補とし、日本語、結合、速度、実行時メモリを測る。モデルサイズだけで端末適合を決めない。
- 確認済みの端末内語彙と、同じ資料中の明瞭な重複情報を候補比較に使う。未知の名称を誤り扱いせず、未確認OCRを正解辞書へ追加しない。別セルの語彙から欠落値を補完しない。

## 評価・性能・再利用

- 内容、フォント、文字サイズ、色、罫線との距離、空欄、結合、並記、ページ分割・順序を変えた独立した架空資料を用意する。調整用と未使用の最終評価用を分離する。
- 描画倍率やPDF内の描画順を変えても結果が変わらないか検証する。実在の学校原本や、その科目・氏名・教室のコピーをテスト・学習に使わない。
- 文書全体の完全成功、正しい拒否、読める資料の復旧失敗、誤採用、元々正しかった箇所の破壊、手動確認数、実行エラー、未評価を別集計する。処理時間と実行時メモリも記録する。
- モデル・項目別に、正しいのに拒否した結果と、誤っているのに通った結果を独立評価資料で測る。文字単位と行全体の不確かさを区別し、同じ入力の反復を独立した成功件数として扱わない。
- しきい値の変更は未使用の評価資料で誤採用が増えないことを確認してから行う。
- 比較対象の索引化と重複検証の削減で高速化する。必要な検証や原文を省いて処理上限を回避しない。
- 認識結果のキャッシュをPDF・ページ・領域・画像・モデル・Runtime・前処理・認識条件へ結び付ける。採用判断の再利用とは分け、Validator変更時は再検証する。
- Windowsのスレッド数・待機設定を速度、メモリ、消費電力、発熱、中断応答で比較する。実行環境で可能な検証は開発側で行い、実行できないものだけ実機へ依頼する。
- 両OSで根拠、位置、信頼度、不明理由、最終判定の意味と架空テストを揃える。各OSの認識エンジンは適したものを使う。
- モデル取得後に通信を遮断して解析を試験する。資料・画像・OCR・Prompt・結果・診断情報を端末内に留め、公開ログへ実資料の文字や画像を出さない。

## 確認訂正と採用画面

- 文書全体で最大3項目の本文訂正という制限を維持したまま、原画像と入力欄を見比べやすくし、対象セルを強調する。十分な大きさを確保し、広い画面では並べ、狭い画面では読みやすく配置する。新しいAIの候補も、見出し・セルの所属・授業数の不明点を質問で埋める経路には使わない。
- 全文プレビューを残し、訂正箇所と比較可能な前回結果からの変更箇所を先に確認できるようにする。比較できない場合は変更を推測しない。
- 原本更新時の無効化、実際の編集による確認解除、背景復帰、全項目確認、全体採用、前回正常結果の保持を実際の画面操作でも検証する。

## 追加候補

- 入力・後処理を改善しても繰り返す誤りには、独立した合成データによる追加学習を比較する。評価用の答えを学習へ混ぜない。
- 学校から許可された構造化元データを取得できる場合の入力経路を別途検討する。現在の対象外形式を無断で取り込み対象に追加しない。
