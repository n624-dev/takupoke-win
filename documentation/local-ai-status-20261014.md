# ローカルAIの現在地（2026-10-14）

**画像PDFを本番で使える精度という目標は未達。現行モデルはPP-OCRv5 mobileのまま。**
以下は独立した架空資料の各固定条件であり、利用者の実資料の成功率ではない。
行・教室値・文書という評価単位や入力が異なる結果を合算しない。

| 対象・条件 | 完全一致 | 意味と制限 |
|---|---:|---|
| 現行V5 mobile、固定原画像の本文 | 90/144（62.5%） | 同じ消費済み192画像の本文、2字体・BGR。高スコア誤読が残る |
| 比較V6 medium、同じ本文 | 111/144（77.1%） | 部品の改善であり、未採用 |
| V6 medium、密帳票1件の教室 | 501/680（73.7%） | 教室だけで179誤読。別字体では見出しに伴う80枠欠落も残る |
| 英語専用V5、英数字のみの正例 | 223/384（58.1%） | 正採用191・誤採用75。紛らわしい英数字は30/96一致 |
| PDF原文の直接取得、修正後の新資料 | 2/2文書 | 限定する描画・構造で全値一致、欠落4件拒否。画像OCRの合格ではない |

本文は科目・担当・教室の全原行で、内部空白や大小文字も含む完全一致を測る。
「正採用」「誤採用」は各研究条件の診断であり、アプリによる採用確定ではない。

方針は、原文を直接取得できるPDFの経路を先に使い、画像PDFでは英数字の取り違えと
セルの取得不足を両方減らすこと。日本語を含む文書全体の取得・負例・原画像との照合を維持し、確認負担と実際の訂正件数を分けて評価する。
OCR文字の誤採用0は今後の導入条件にせず、誤り率を低減し利用者が見直せることを重視する。

既知字体の全文描画照合では、高スコア誤読18行を拒否し正128行を保持したが、
教室の取得は15/48に留まった。未知字体・スキャンの精度やUnicode一意性は未証明で、
安全性を補う研究候補である。認識器同士の一致だけでも共通誤読が残る。

追加学習は選択肢の一つ。英語V5の転移準備は初期数値一致の固定ゲートに届かず、
学習未開始で閉じた。学習後の精度を測った結果と混同しない。
GLM-OCRは以前のGGUF Q8結果を保持し、公式非量子化版を別条件で比較する。
公式FP32・CPU4の192件は完了し、本文99/144（68.8%）、教室25/48。
空画像6件は全て空のMarkdown枠を出した。生の形式と本文の空を区別し、不採用。

Winの本文訂正は`codex/pdf-local-recovery`（e0275d2）から現在のブランチへ既に含まれていた。
既存UIを再利用し、高信頼度で誤読した本文の明示選択と、変更なしの確認を実際の訂正から
分ける経路を実装した。NativeConfidenceは保持し、原画像・出典・更新検知・明示採用を維持する。
型付きの取得／訂正記録schema2は、変更なしの確認と実際の本文訂正を分ける。
確認は最大128項目、文字の訂正は資料全体で最大3項目。既存schema1の意味と上限は維持する。
原画像を同じ寸法で再描画し、元ページの画素SHAを確認してから訂正画面へ進む。


Linux全体検証はIntegration937・Core288通過。関連106件では高信頼度の本文訂正、
確認のみの4項目、3訂正／4訂正の境界、原文とscore保持、更新／欠落／変更された
プレビューの拒否、再起動・中止復帰・古い入力sessionの失効を確認した。
これらは製品フローの検証であり、画像OCR精度の資格を示すものではない。
