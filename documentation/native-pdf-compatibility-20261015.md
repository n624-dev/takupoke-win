# 文字情報を持つPDFの取り込み改善（2026-10-15）

罫線・色付き背景・縁取り文字・矩形の表示範囲を含むPDFが、文字認識を始める前に停止していた。原本に埋め込まれた文字、フォント、描画位置と実際の字形を照合し、確認できる文字情報を優先して使う。モデルや学習済み重みは変更していない。

従来のStrict readerは維持する。通常の取り込みはStrictを先に試し、独立したnative描画照合が完了して未確認文字がない場合に限り、追加の描画互換経路を使う。OCRモデルの取得やAI設定のONは必要ない。部分的な文字の切れ・罫線との重なりが残る場合は、自動取り込みせず、AI・OCR設定をONにした確認経路へ進む。

確認経路では元の文字列とnative出典を保持し、OCRとして扱ったり、架空のconfidenceを付けたりしない。元PDFから描画したページと切り抜きのSHAを照合する。本文は訂正でき、見出し・注記は同じ文字列を原画像で確認する。新しい確認記録はschema4を使い、従来のschema1／2／3と保存済みの記録はそのまま検証する。

欄分けでは、短い欄に合う位置基準を使い、異なる字体の無関係な基準だけで全体を拒否しない。返却表の学年は、印字の中心への近さより物理的な罫線の所属を優先する。上下に分割された同一時限の授業も保持する。native試験表の2行形式は、上段の科目・中段の教員・印字のない教室として扱う。下側の2行を科目・教員へ繰り上げない。

専攻科の学年だけの見出しは、完全なnativeの6ページ形式、別に印字された通常15クラス、2つの学年見出し、隣接する6時限の物理的な見出しをすべて確認した場合だけ使う。OCRや不完全な資料へこの条件を流用しない。全角数字・全角コロン・離れた時刻断片も、元の文字片を保持して照合する。

表の外にある原本の注記は、授業の本文や空欄の証拠と分けて保持し、確認画面から開ける。注記による特別な教室指定や時間の条件を、本文の認識精度と混同しない。原PDFも併せて確認する。

提供された時間割・返却表・試験表では、通常取り込みまたは原画像確認へ進む経路まで検証した。時間割は680枠で3項目、試験表は510枠で注記見出し1項目が確認対象となった。返却表は未確認の文字がないnative経路で解析できた。nativeの別経路同士で値の対応も照合したが、これは独立した人手正解率や画像OCRの精度ではない。利用者本人の確認・訂正時間、未知の帳票での成功率は未測定である。

実資料のPDF・原文・画像・個人名・切り抜きは公開するテストや研究データに含めず、追加学習にも使わない。検証後、開発環境の原本3件と派生ファイルを削除済み。リポジトリには一般化した実装と、独立した架空資料のテストを保存する。

ローカルの回帰検証はIntegration 1071件、Core 288件が通過した。[Windowsを含むCI](https://github.com/n624-dev/takupoke-win/actions/runs/38711108154)も全7ジョブ成功。Windowsの829 UI項目で、native原画像・本文訂正・見出しと注記の確認・明示採用・保存後の再起動を検証した。公開テストは独立した架空資料を使い、実資料の精度評価とは分ける。Node.js 20の警告は全7ジョブで0件だった。
