# 復旧OCRと訂正支援の改善（2026-10-16）

この記事は配布10445の記録。新しい既定構成・全文書検証は[切り出し・再認識・順序の改善](ocr-source-order-accuracy-20261016.md)を参照。

復旧用の低スコア英数字を元のconfidenceのまま原画像確認へつなぎ、名称対応表から教室名の候補を表示する。
原OCR・出典・画像を保持し、確認チェック、全体プレビュー、明示採用を経て取り込む。
日本語PP-OCRv6 medium＋学習済み英数字PP-OCRv5 font-balanced v1、CPU用約99 MiBのモデル構成は変えない。
追加生成AIは採用しない。iOSは参照のみで編集していない。

両画像集合は通常コード192件・I/l/1/O/0の難例192件という人工的な半々の構成で、本番の出現割合ではない。
通常部分は単独190/192・日本語付き189/192一致。残る誤読92件中90件／89件は難例側だった。
[既存原出力による誤読内訳](../research-results/ocr-accuracy-20261016/remaining-errors-diagnosis.json)。

通常コードにも退行が残る。必須確認の画像は単独コード55→143、日本語付き64→121と増えた。
帳票では必須確認4→11／0→2、高スコア誤読27→24／23→23。confidenceだけで誤読を検出し切れないため、
従来のプレビューから高信頼度の欄も選択して訂正できる。1文書の確認・訂正は最大128項目を維持する。
各画像試験の384件は1文書ではない。実資料の正解率・人の照合や訂正時間は今回測っていない。

候補は名称対応表に実在する教室の文字列だけ。I/l/1・O/0の最大2違いを照合し、
日本語・空白・他の文字は完全一致が必要。順位は相違数・文字列順で、確率ではない。
別クラスの登録を除き、最大3候補を示す。候補を押した後も画像確認が必要で、自動訂正はしない。
正しいOCRや登録のない教室にも別候補が出るため、確認せずに候補を選ばない。

追加学習v2は独立字体のcropでは360→368/384一致だったが、実際の復旧経路は292→292で、
文字編集106→123・高スコア誤読24→36へ悪化した。このため既定はv1を保持する。
v2は[仕様付きの標準ONNX](../model-artifacts/ascii-english-v5-confusion-v2/README.md)を研究候補として公開する。
iOSで使える入出力仕様だが、CoreML・iPhone実行は未確認。

Windowsの架空5ページは、物理2/論理4CPU・約16GiB RAMで36.705秒／30.372秒、
全6文書のreader最大working set約558MiB。モデル取得・人の確認時間は含まない。
異なるrunnerの過去時間との差を高速化とは扱わない。誤読0を条件にせず、残る誤読と確認負担を明記する。
