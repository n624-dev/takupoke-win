# OCR精度改善の参考候補

利用者が提示したOCR一般の25案とPDF向けの22案から、未実装の改善候補だけを保持する参考資料。全項目を今すぐ実装する指示ではなく、改善が頭打ちになった際に原因と比較実験に応じて候補を選ぶ。

確定した未実装方針は[PDF復旧・OCR・ローカルAIの未実装方針](pdf-recovery-pending-policy.md)を参照する。実装できた項目は削除し、一部だけ残る項目は未実装部分に絞る。この参考資料には完了記録・進捗・実測値・作業メモを追加しない。番号は元の助言との対応用で、削除後に詰め直さない。

## 採用時に維持する条件

- Strict Parserを最優先にし、取得できた文字・座標・罫線を再利用する。
- OCR・AIの推論は端末内のみ。リモートOCR、リモート推論、Private Cloud Computeへの自動切替を使用しない。
- PDF、PDF画像、OCR文字、科目・教員・教室、Prompt、RecoveryResult、実資料の診断ログを外部へ送らない。モデル取得は資料処理と分離し、ダウンロード要求に資料やPromptを含めない。
- 学校原本PDF、その科目・教員・教室の文字列をテスト・学習に使わない。比較・学習用には独立した架空データを作る。
- 原文・原画像と正しいセルへの根拠照合、決定論的Validator、利用者確認を維持する。多数決・文脈・辞書・モデル同士の一致だけでは採用しない。
- 手動訂正は文書全体で本文最大3項目。見出し・構造・授業数の不明点を入力で埋めない。
- 元資料にない細部を超解像で作った場合や擬似ラベルは、確認済みの原文根拠として扱わない。
- 今回のiOS・Windows配布後、すべての改善と合格基準の検証が終わるまで追加の中間版を公開しない。

## モデル・エンジン

1. **複数エンジンのアンサンブル**：PaddleOCR、NDLOCR、Tesseractなど端末内エンジンをROVER方式で文字単位に照合する。元の助言にあるクラウドOCRは採用対象外。
2. **VLMで直接OCR**：Qwen3-VL、InternVL、GOT-OCR2.0、PaddleOCR-VL、dots.ocr、DeepSeek-OCRなどのローカル実行。
3. **OCR結果と画像をVLMに渡して後補正**：「誤認識を直して」と指示する二段構成。訂正候補と採用を分ける。
4. **分離した検出・認識モデルの個別最適化**：DBNet／YOLO、PARSeq／SVTR／TrOCRなどの代替モデルを固定条件で比較する。
5. **ドメイン特化ファインチューニング**：認識モデルやVLMへのLoRA。独立した合成データを使う。
6. **合成データの追加生成方式**：SynthTIGER等で、現行の架空資料にない背景・劣化条件を独立した評価資料へ追加する。
7. **蒸留**：端末内の大型VLMで疑似ラベルを作り、軽量モデルへ学習させる。未確認ラベルを正解扱いしない。
8. **ハードサンプルマイニング**：低信頼度の合成サンプルを人が修正して再学習する（アクティブラーニング）。

## 画像側

9. **TTA（推論時拡張）**：複数スケール、二値化、コントラストで別々に認識し照合する。
10. **文字領域のみ超解像**：Real-ESRGAN、SwinIR。
11. **学習ベースの歪み補正**：UVDoc、DocTrなどのdewarping。
12. **学習ベースの影除去・二値化**：通常の二値化では限界がある場合。
13. **オーバーラップ付きタイル分割**：高解像度画像をVLMに入れるときに使う。
14. **マルチフレーム統合**：連写や動画から複数フレームを合成する。
15. **向き・縦横書きの自動判定**：行単位の切り出し精度を上げる。

## 後処理

16. **LLMによる文脈補正**：元OCRとの編集距離に上限を設け、訂正候補を根拠と照合する。
17. **N-best／beam候補を保持して再ランク**：辞書やLMを候補比較に使う。
18. **混同ペア補正**：0/O、ー/一、1/lなどの誤り傾向を学習する。置換を自動確定しない。
19. **ドメイン制約の追加**：端末内の確認済み語彙との比較と、原本に実在するチェックデジットの検証。語彙だけで未知の名称を訂正しない。
20. **Windowsの生成時制約**：対応するローカルProviderでJSON Schema／文法による制約デコーディングを比較する。出力後の型・内容検証は引き続き必要。
21. **VLMの複数回サンプリング＋自己一貫性**：固定した複数条件で候補を比較する。多数決だけで採用しない。
22. **レンダリング比較**：候補を同じフォントで描画し原画像との差分を見る。フォント一致を確認できない場合は検証済みと扱わない。

## 運用・設計

23. **信頼度キャリブレーション＋カスケード**：軽量モデルで処理し、不確かな領域だけ重いローカルモデルや人手へ回す。
25. **文字誤り率と分類の追加**：既存の独立した架空評価へCERと混同文字・欠落・挿入の分類を加え、文書全体の評価とは別に弱点を測る。

## PDF向けの候補

### PDFならではの手がかり

1. **文字取得失敗時のベクター罫線取得**：文字・ToUnicodeの取得に失敗しても、安全に読み取れる描画パスを別に取り出す。未対応のクリップ・変換・重ね描きがあるページを完全取得と扱わない。
2. **アウトライン化グリフの形状照合**：字形パスを変換・塗り・クリップ条件も含めて照合し、同形状を集約する。OCR一回の判定を無条件で全出現へ展開せず、誤読の一括伝播を検証する。
3. **欠損・壊れたToUnicodeの復元候補**：埋め込みTrueTypeのType0／CIDFontType2では、文字コード→CID→CIDToGID→フォントcmapの一意な逆対応を先に比較する。cmap間の矛盾、複数Unicodeへの対応、GID0、可視性不明は拒否し、対応の出典を保持する。CFF・Type3は別に検討する。直接対応が得られない場合は、フォントとグリフIDごとに原画像からOCR候補を得る。対応表は同じフォント資源内に限定し、既存Unicodeや別描画との不一致を未解決として保持する。
4. **文字コードが不正なグリフの座標利用**：復号できなかった文字の位置情報を保持し、OCRの領域と照合する。座標の正しさもページ変換・原画像で検証する。
5. **埋め込み画像のネイティブ抽出**：元画像を再サンプリングせず取り出す。マスク、色空間、配置変換、重なりを確認し、画像単体がページ全体の見た目と同じとは決めない。
6. **セル背景色の取得**：背景色を構造の補助情報に使う。変更・休講・振替の意味は原本の凡例や注記がある場合だけ解釈する。

### 表の構造

7. **セル単位のOCR**：根拠のある罫線・セル境界から原画像を切り出す。文字の欠け、結合セル、隣セルの混入を確認し、セル内の文字領域検出と認識を比較する。
9. **表構造認識モデル**：Table Transformer、SLANet、TableFormerなどの端末内実行。罫線・文字位置・結合範囲との一致を別に検証する。
10. **テンプレートとアンカー補正**：確認済みのレイアウトに限り座標テンプレートを候補とする。見出し・罫線・ページ範囲の一致が取れなければ使用せず、変更された形式に旧配置を押し付けない。
11. **項目ごとのOCR設定比較**：科目・教員・教室の別が原本の構造から確認できる場合に設定を使い分ける。設定と試行回数は事前に固定し、期待する文字へ誘導しない。
12. **小さい補助文字の別経路**：教室・略称などを必要領域だけ原本から高解像度で描画して読み直す。認識直前の縮小も測り、拡大画像にない細部を推測しない。

### 構造・辞書による検証

14. **確認済み語彙との照合**：利用を許可された科目・教員・教室一覧を端末内で候補比較に使う。ファジーマッチは再確認の手がかりに限定し、自動置換や未知語の拒否に使わない。
15. **前回資料との差分で検証順を決める**：変更候補を重点確認する用途に限る。前回と同じだから採用する、前年度から欠落値を埋める、未変更部分の根拠検証を省く、といった使い方はしない。
16. **単位数・週コマ数の検算**：原本に根拠付きの合計と集計範囲が載っている場合に照合する。一般的な授業数を推測して補わない。
17. **許可された別資料との端末内照合**：利用者が取得を許可した学校の元データ・お知らせを補助情報として比較する。資料やOCR文字を外部サービスへ問い合わせず、今回のPDFの根拠を別資料で置き換えない。

### VLM活用

18. **表全体とセル結果の比較**：端末内VLMのHTML／JSON構造化結果とセル単位の結果を照合し、不一致箇所だけ再確認する。両結果の一致だけでは正解と扱わない。
19. **セル画像と周辺文脈の再認識**：原画像、位置、根拠のある見出しを局所的に渡す。初回はOCRの答えを伏せる条件も比較し、文脈による文字の創作を検出する。
20. **ネイティブPDF入力の比較**：ローカル実行とPDF入力の対応が確認できたモデルだけを候補とする。ページ・セル群ごとの上限を設け、PDFをクラウドサービスへ渡さない。

### 運用

22. **未対応描画の取得経路判定**：アウトライン化・文字化け・画像と文字の混在を区別し、グリフ・パス・埋め込み画像の取得経路を選ぶ。途中取得を完全なページとして扱わず、既存の取得状態・根拠検証へ接続する。

## 色比較の条件

文字・フォント・大きさ・配置・背景・切り出し範囲を固定し、色だけを変える。元の色と、明るさを保って色味を除いた画像を別条件で測る。色相と明るさの違いを混同せず、文字一致率、正読の自身信頼度、高信頼度の誤読、文書全体の採用可否を分けて評価する。
