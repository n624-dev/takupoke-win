# OCR精度改善の参考候補

利用者が提示したClaudeの25案を保持する参考資料。全項目を今すぐ実装する指示ではなく、改善が頭打ちになった際に原因と比較実験に応じて候補を選ぶ。

確定した未実装方針は[PDF復旧・OCR・ローカルAIの未実装方針](pdf-recovery-pending-policy.md)を参照する。この参考資料には進捗・実測値・作業メモを追加しない。

## 採用時に維持する条件

- Strict Parserを最優先にし、取得できた文字・座標・罫線を再利用する。
- OCR・AIの推論は端末内のみ。リモートOCR、リモート推論、Private Cloud Computeへの自動切替を使用しない。
- PDF、PDF画像、OCR文字、科目・教員・教室、Prompt、RecoveryResult、実資料の診断ログを外部へ送らない。モデル取得は資料処理と分離し、ダウンロード要求に資料やPromptを含めない。
- 学校原本PDF、その科目・教員・教室の文字列をテスト・学習に使わない。比較・学習用には独立した架空データを作る。
- 原文・原画像と正しいセルへの根拠照合、決定論的Validator、利用者確認を維持する。多数決・文脈・辞書・モデル同士の一致だけでは採用しない。
- 手動訂正は文書全体で本文最大3項目。見出し・構造・授業数の不明点を入力で埋めない。
- 元資料にない細部を超解像で作った場合や擬似ラベルは、確認済みの原文根拠として扱わない。
- 今回のiOS・Windows配布後、すべての改善と合格基準の検証が終わるまで追加の中間版を公開しない。

## モデル・エンジン

1. **複数エンジンのアンサンブル**：PaddleOCR、NDLOCR、Tesseractなど端末内エンジンをROVER方式で文字単位に照合する。元の助言にあるクラウドOCRは採用対象外。
2. **VLMで直接OCR**：Qwen3-VL、InternVL、GOT-OCR2.0、PaddleOCR-VL、dots.ocr、DeepSeek-OCRなどのローカル実行。
3. **OCR結果と画像をVLMに渡して後補正**：「誤認識を直して」と指示する二段構成。訂正候補と採用を分ける。
4. **検出と認識を分離して個別に最適化**：検出はDBNet／YOLO、認識はPARSeq／SVTR／TrOCR。
5. **ドメイン特化ファインチューニング**：認識モデルやVLMへのLoRA。独立した合成データを使う。
6. **合成データ生成**：フォント、背景、劣化をシミュレートする（SynthTIGER等）。
7. **蒸留**：端末内の大型VLMで疑似ラベルを作り、軽量モデルへ学習させる。未確認ラベルを正解扱いしない。
8. **ハードサンプルマイニング**：低信頼度の合成サンプルを人が修正して再学習する（アクティブラーニング）。

## 画像側

9. **TTA（推論時拡張）**：複数スケール、二値化、コントラストで別々に認識し照合する。
10. **文字領域のみ超解像**：Real-ESRGAN、SwinIR。
11. **学習ベースの歪み補正**：UVDoc、DocTrなどのdewarping。
12. **学習ベースの影除去・二値化**：通常の二値化では限界がある場合。
13. **オーバーラップ付きタイル分割**：高解像度画像をVLMに入れるときに使う。
14. **マルチフレーム統合**：連写や動画から複数フレームを合成する。
15. **向き・縦横書きの自動判定**：行単位の切り出し精度を上げる。

## 後処理

16. **LLMによる文脈補正**：元OCRとの編集距離に上限を設け、訂正候補を根拠と照合する。
17. **N-best／beam候補を保持して再ランク**：辞書やLMを候補比較に使う。
18. **混同ペア補正**：0/O、ー/一、1/lなどの誤り傾向を学習する。置換を自動確定しない。
19. **ドメイン制約**：語彙との比較、日付・番号のフォーマット、チェックデジットを検証する。
20. **構造化出力の制約デコーディング**：JSON Schema／文法で出力形式を制約する。
21. **VLMの複数回サンプリング＋自己一貫性**：固定した複数条件で候補を比較する。多数決だけで採用しない。
22. **レンダリング比較**：候補を同じフォントで描画し原画像との差分を見る。フォント一致を確認できない場合は検証済みと扱わない。

## 運用・設計

23. **信頼度キャリブレーション＋カスケード**：軽量モデルで処理し、不確かな領域だけ重いローカルモデルや人手へ回す。
24. **差分箇所だけの確認UI**：エンジン間で不一致の箇所を見比べる。本文最大3項目という条件を保つ。
25. **評価基盤の整備**：独立したゴールドデータでCERを測り、誤りを分類して弱点を特定する。文書全体の成功・安全な拒否・誤採用・実行エラーも分けて測る。

## 色比較の条件

文字・フォント・大きさ・配置・背景・切り出し範囲を固定し、色だけを変える。元の色と、明るさを保って色味を除いた画像を別条件で測る。色相と明るさの違いを混同せず、文字一致率、正読の自身信頼度、高信頼度の誤読、文書全体の採用可否を分けて評価する。
