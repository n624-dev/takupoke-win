# 選択済み資料の更新を再選択なしで取得する未実装方針

登録した同じ絶対パスの最新版を更新対象にする。ファイルIDの変更だけで再選択を要求しない。
別フォルダーや似た名前の資料を探索して選ばない。移動・削除・アクセス不能は前回正常結果を
保持して更新失敗を示す。

前回保存したIDとの一致と、一回の読み取り中の同一性確認を分ける。
今回開いたハンドルのファイルID、長さ、更新時刻、同じパスの読み取り終了時の対象を確認する。
読み取り中の差し替え・書換え・同期途中は完成した入力として保存しない。
同期途中の再試行は有界にし、取消しと期限を維持する。ファイルID取得をUI threadで実行しない。
形式・サイズ・拡張子・一時Excelファイル・リンクの拒否と保存期間の検証は維持する。

前回とSHAが同じなら、解析結果を再利用し、現在の取得識別情報を更新する。
本文不変のID更新だけで、新たな授業・通知・除外許可の失効を生まない。
SHAが変われば新しい原本として保存・再解析し、曜日行の除外許可と開いている確認内容を失効させる。
前回の正常結果と、その結果に対応する旧原本は、新入力の解析失敗・取得失敗でも保持する。
新しい選択情報と取得識別情報の更新は、保存失敗時に部分反映しない。

変更通知、起動・復帰、周期確認、手動更新は共通の再取得経路を使う。
保存したコピーだけを読む再解析と、選択パスからの最新版の再取得を区別する。
取得条件の緩和を確認画面の正式採用へ流用しない。行除外の採用直前には、
確認したSHA・選択元・年度・Parser版・行を再確認し、更新された入力への古い許可を拒否する。

同じIDでの更新、同じパスでIDだけ変更、IDとSHAの両方変更、更新中の差し替え、削除、
無効形式、取得取消し、保存失敗、再起動後の更新を独立した架空資料で検証する。
ID変更を一律拒否する既存ケースを仕様変更として更新し、読み取り中の差し替えと
古い確認の採用拒否は別の負例として残す。Windows実機の実ファイルID確認を偽物のIDテストと区別する。
