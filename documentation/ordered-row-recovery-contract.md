# 原文3行を保持する通常時間割の復旧契約

Strict Parserの失敗後、取得が完了した原文の文字・位置・罫線を再利用する。新しい経路は通常時間割の17クラス、月〜金、1〜8限の680セル全体に限定する。1セルは未結合の1時限で、科目・教員・教室の3行がすべて非空であることを要求する。本文に役割ラベルや並記の区切りがある場合には、この行順の経路を使用しない。

各行は元の文字単位、同じ非負のsourceLine、増加するsourceOrder、重ならない文字位置を保持する。非空白文字間の距離が隣接文字高の1.5倍を超えた場合、離れた本文を一つの行として扱わない。行同士にも縦方向の重なりを許可しない。全3行の文字と根拠を保持し、値を推測・省略・補正しない。

取得元の行証明はアプリが作成する。Validatorは原文ID、文字、位置、ページ、セル、行順、全クラス・曜日・時限の所属を再確認する。モデルが行証明を出力しても採用しない。証明を除いて役割を入れ替えた結果も、全体の縦方向の役割対応で拒否する。

iOSとWindowsはこの意味を共有する。iOSは1行に集約した原文IDと元の文字群、Windowsは文字ごとの原文IDと元の文字群を保持する。原文の空白を含む値はそのまま保存する。Strictへ渡す既存の文字列は維持し、復旧用captureへ明示的に描画された空白を追加する。空白の位置を取得できなければ、captureをpartialとしてRaster経路で再取得する。

Windows Validatorは10へ更新する。元の4〜9の確認結果を変更せず再検証し、既存の8→9の確認証明も保持する。新しい行証明を古いValidatorで確認済みと偽装した結果は拒否する。追加モデルの合格や本番OCRの精度は、この意味契約のテスト成功から推定しない。

`tools/ordered-row-e2e`は独立して描画した架空PDFだけを使用する。期待値をReader・Builder・Rules・Validatorへ渡さず、正式な結果が返った後に680キー・2040値・年度・学期を比較する。文字PDFの結果はOCRの精度には数えない。生成したPDF・フォント・原観測は所有する一時ディレクトリへ置き、Actionsの最後に削除する。保存artifactやcacheは作成しない。
