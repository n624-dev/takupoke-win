# 試験PDFの表ごとの適用範囲

初回Linux .NET 10.0.404の全体検証は351成功・10失敗。
AppLifecycleの通知用fixtureが現行Parser版に対して適用範囲を省略していた。
fixtureの既存1クラス・1日・1ページを明示し、保存側の新規scope検査を維持した。
機密PDFはリポジトリ外でのみ検証し、本文・画像・派生ファイルを公開物へ含めない。

## 実装

現行の特殊Parser10（初版は9）。試験は最大12ページの各ページ1表で、時限見出し1〜6の繰返しから列数を決め、
本科／専攻科のクラス見出しと日付行を読む。ページ番号をクラスの判定へ使わない。
1表31日・64列と既存の処理上限を維持し、クラス・日付の重複、未割当の本文、
別クラス・別日へ跨ぐセル、年度・時刻の矛盾を拒否する。
「全Nページ」の明記があれば照合する。明記がないPDFから欠落の有無を完全に証明はできない。
返却の既存規則は維持する。

SpecialScopeは各表のページ・クラス・日付を保存し、和集合同士の直積を適用範囲にしない。
保存前にも検証し、旧保存は従来の範囲で読み、現行Parserで再解析する。
失敗時に前回正常結果・原本を保持し、新資料へ旧資料の未掲載授業を混ぜない。

文字の選択矩形と可視インクの矩形を分け、後者で色・クリッピングを検査する。
特殊PDFの単一軸平行矩形クリップだけは、CTMとq/Qを反映し、
判定対象の文字本体・描画が領域内にあることを確認して受理する。
不可視文字・透明度・複合／曲線クリップと、クリップを跨ぐ内容の拒否は維持する。
塗り罫線の交点をセル背景と誤認せず、部分的な先行背景は全候補色とのコントラストを検証する。
後描画の覆いと文字のコントラスト不足は拒否する。

## 全差分の再確認で見つかった輪郭の上塗り検出漏れ

19bd60bの配布0.1.0-dev.10460は全CIとSetup検証後に公開したが、利用者指示の全差分確認で
特殊PDFの可視性境界を追加照合した。機密資料を使わず、独立した実フォントの「架空」2文字と
離れた罫線だけの入力で、輪郭描画の文字本体矩形の外側に白い矩形を後描画した。
本体内への上塗りはP01、輪郭だけへの上塗りは受理となった。
同じ架空入力を変更前228b593でも実行し、輪郭だけへの上塗りをP01で拒否することを確認した。
最初の補助probeは罫線を省略していたためlayoutのlimitで止まり、無関係な罫線を加えて
Readerの前提を満たした後にこの差を確認した。無効な初回入力を不具合の証明には数えない。

原因はclip用に導入したtight glyph矩形をpaint検査にも使い、輪郭の幅を含めていなかったこと。
候補は既存のCTM/線幅/join/miter上限をpaintにも適用し、塗り本体だけで証明する例外は
既存どおり同じ不透明色のmode2だけに限定する。clip外のhairlineは元の選択矩形の扱いを保持する。
共通paintの新しい部分背景／塗り罫線の検査は特殊PDFに限定し、通常時間割の受理規則と版11を維持する。
特殊Parserは10へ進め、既存version9の解析／失敗も原本を再検査する。期限切れ・不明な可視性を成功にしない。

修正前の新しい実フォント回帰3入力は2失敗・1成功。輪郭のみmode1と色の異なるmode2で
期待したP01が出ず、同色mode2の完全な塗りが残る陽性は成功した。入力と期待を維持して修正する。

輪郭範囲の修正と通常／特殊の背景規則の分離後、可視性87入力が失敗0で成功した。
この限定成功だけで再配布せず、全体のCore/Integration/Platformと配布CI・Setup検証へ進む。
