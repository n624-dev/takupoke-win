# mainの機能とローカルAI・OCRの統合

mainの`944662b277f7d8eb31e3ce66f6a447c822144561`を、AI・OCR側の変更と合わせて取り込んだ。main固有の34コミットを履歴にも含め、XLSXの問題行を選んで除外する操作と、同じ曜日だけの連続行をまとめて除外する表示を追加した。10440にはこの行除外機能は含まれない。

日付から曜日を求める既存の補正も保持する。行除外と曜日補正はそれぞれ原本・年度・解析条件に結び付け、片方の許可で他方を許可しない。両方の許可を持つ保存結果も、更新・再解析・再起動で保持する。元ファイルは書き換えない。解析仕様の統合に伴い、XLSX parser versionを6にし、以前の条件の確認を新しい条件へ無断で流用しない。

PDF原文字の拡張経路、原画像と切り抜きの検証、OCRモデル、本文訂正、見出し・注記の確認、最大128項目の確認予算、旧記録の検証は維持する。今回、OCRモデルや重みは変更していない。提供された実資料は削除済みで再取得せず、テスト・学習・公開データに使わない。iOSは編集しない。

mainのテスト一覧・変更対象検索とCI検査を導入し、既存のAI・OCR・native PDFのソースとテストも登録した。UIテストはmainの責務別ファイルを使い、AI・OCRのシナリオを併合した。行除外の取消し・確認・採用・再起動に加え、曜日補正の取消し・採用・全行保持・再起動も実コントロールで確認する。新規配布ブランチのbeforeがゼロSHAの場合は、テスト一覧の既存のHEAD親への比較を使い、無効なSHAの比較を避ける。

ローカルではIntegration 1093件、Core 288件、テスト一覧ツール14件、Windows操作検証プログラムのクロスビルドが通過した。独立した行除外と曜日補正の両許可を必要とする保存、許可不足時の原子的な拒否、再取得・再解析・再起動、日付補正で曜日だけの行を暗黙に捨てないことを追加検証した。既存ケースはPDF・OCRの回帰とmainの行除外・原本更新を検出するため維持し、不要な期待値の変更や件数削減はしていない。

認証コールバックを既存プロセスへ転送する起動側は、STAでCOM呼び出しを処理できる待機方式に変更した。[Microsoftの単一起動方式](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/applifecycle/applifecycle-single-instance)に沿ってイベントと`CoWaitForMultipleObjects`を使い、転送の例外も呼び出し元へ返す。既存の実画面認証ケースが、不正stateの拒否、有効なraw URIとWindowsプロトコルの転送、転送プロセスの10秒以内の正常終了、トークン交換・取消し・保存を検証する。期限や成功条件は緩めない。テスト自身が起動したraw URIプロセスは失敗時にも終了させ、導入先のランタイムを掴んだまま残さない。
