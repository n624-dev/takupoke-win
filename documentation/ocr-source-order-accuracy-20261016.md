# OCRの切り出し・再認識・文字順序の改善（2026-10-16）

新しい2フォントファイル・各5ページの架空時間割で、本文344/360項目と355/360項目が一致した。
文字誤り率は16/2906＝0.5506%と7/2895＝0.2418%。両方とも120/120枠、本文360項目を保持し、欠落・余分・重複0。
[Windows実行38836313175](https://github.com/n624-dev/takupoke-win/actions/runs/38836313175)で旧処理との比較と訂正経路を確認した。
ソースの既定経路へ接続した。配布状況と導入検証は[最新Release](https://github.com/n624-dev/takupoke-win/releases/latest)とREADMEの配布記録を参照。

CPU・メモリ16GBを想定し、日本語PP-OCRv6 medium＋英数字PP-OCRv5 font-balanced v1を基礎に、
日本語フォントで調整したV3 epoch1を復旧の英数字コード補助へ追加する。合計125,753,061バイト、約120 MiB。
新構成の利用には設定からモデルの更新が必要。元のv1は補助が成立しない場合の経路として保持する。
学校資料は端末内で処理し、モデル取得時には固定URLのモデルファイルだけを取得する。

iOSは参照のみで変更していない。V3は標準ONNX FP32・438文字辞書・opset17で仕様を公開しているが、
CoreML変換・iPhone実行を確認したものではない。元モデルは公式英語PP-OCRv5を基盤とするv1 epoch4。

今回直したのは、罫線に接した印字の切り出し、末尾が入力余白に重なった場合の実再認識、
低スコアの項目名・区切り記号の原画像からの再認識、数字だけの不確かな補助読み取り、同じ行の文字順序。
特に英数字の切り出し高さが変わると「架空室3B」が「3B架空室」になる不具合を修正した。
行全体の元の順序・左右位置・重なり・罫線との関係を検証できた場合だけ、元の文字順を保持する。
認識文字、native confidence、CTC位置、元画素を手で書き換えて測定値を上げる処理は行わない。

新しい2資料の必須確認は42項目／6項目、参照誤読とのunionは48／9で128項目以内。
高スコアの誤読も6／3項目残る。実際の人の訂正時間は測っていない。
曜日・クラス欠落の新4負例は全ページの取得後に拒否し、旧12負例も拒否を維持した。

新2資料はWindows・物理2／論理4CPU・約16GiB RAMで41.857秒／46.111秒、ワーカー全6資料の最大working set約517MiB。
モデル取得・初期ロード・PDF描画・人の確認時間は含めない。別runnerの過去値との比較を高速化の根拠にはしない。
鮮明な架空の罫線付き帳票での結果であり、実学校資料・傾きや汚れのあるスキャン全般の成功率ではない。

元のV3単独学習試験は登録済みの10%改善条件を満たさず、元のFAIL判定を保持している。
今回の採用判断は、事前に固定した別の実経路比較による。最初の全文書試験もMPLUS2の文字誤り35→55でFAILとなり、
文字順序の不具合を修正後、新しい資料で確認した。FAILした試験を後からPASSには書き換えない。
追加学習V4は独立資料のコード精度と実経路で改善を確認できず、採用しない。

文字情報のあるPDFは従来の通常解析を優先する。画像OCRを利用する場合は、モデルを更新して資料を読み直し、
プレビューで科目・教員・教室を原PDFと照合する。必要な欄を選択して訂正し、全体プレビューを確認して明示採用する。
名称対応表は訂正候補の表示に使い、OCRの一致数には含めない。原画像cropで判断しづらい場合は対応する元PDFを開ける。
提供された実PDF・派生画像は今回の比較・学習に再利用していない。内部の作業方針Markdownは公開しない。
